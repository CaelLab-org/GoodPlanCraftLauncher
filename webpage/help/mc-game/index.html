游戏崩溃了怎么办

崩溃窗口本身通常看不出原因。先导出错误报告，再按下面的顺序排查。

先做一件事：点崩溃弹窗上的「导出错误报告」，把生成的 zip 保存下来。报告里有崩溃报告、游戏日志、启动器日志和系统信息，排查基本都靠它。

1. 导出错误报告

崩溃弹窗上就有这个按钮。选一个位置保存，GPCL 会打包：

  • 崩溃报告（如果有）
  • 最近一次游戏日志
  • 启动器日志和启动参数
  • 系统内存、Java 和操作系统信息

报告里的 --accessToken 已经打码，可以直接发出去。不要只发崩溃窗口的截图。

2. 自己先看日志

弹窗上的「查看日志」会打开游戏进程的输出。重点看最底部，以及搜这几个词：

  • Exception、Caused by：真正的异常通常在第一个 Caused by 后面。
  • OutOfMemoryError：内存不够。
  • UnsupportedClassVersionError：Java 版本和游戏版本对不上。
  • NoSuchMethodError、ClassNotFoundException：多半是模组和游戏版本、加载器版本不匹配。

3. 常见原因

现象常见原因怎么处理
一启动就退出，日志里有 UnsupportedClassVersionError Java 版本不对 让 GPCL 自动补 Java；或在设置里换 Java 镜像源后重新安装。
加载到一半卡死或闪退，日志里有 OutOfMemoryError 分配内存不够，或模组太多 设置 → 游戏 → 内存分配里调大；不要超过物理内存。
加载模组时崩，日志里出现模组名 模组版本不对、缺前置、两个模组冲突 先只装这个模组试；确认它支持的 MC 版本和加载器版本。
窗口还没出来就退出，有 GLFW error 显卡驱动过旧，或 OpenGL 不支持 更新显卡驱动；笔记本确认游戏用的是独显。
进服务器被踢，提示 Invalid session 正版登录过期，或账号没有这个版本的授权 重新登录正版；确认账号确实拥有该版本。
进世界或加载资源包时崩 存档、资源包或光影包损坏 先新建一个世界试；把存档备份出来再处理。

4. 先排除这三件事

  1. 关掉所有模组、资源包和光影，裸启动一次。能进就是模组那边的问题。
  2. 换一个原版版本启动。能进就是当前版本或它的模组组合有问题。
  3. 新建一个世界。能进就是原来的存档坏了。

5. 求助

发邮件时附上错误报告，再写清楚：游戏版本、装了什么模组、崩溃前做了什么、能不能稳定复现。
