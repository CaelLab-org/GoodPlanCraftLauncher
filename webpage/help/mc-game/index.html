游戏崩溃了怎么办

GPCL 弹出「Minecraft 出现错误」的时候，窗口本身说明不了问题。下面这几步能帮你把原因找出来，也让别人有机会帮你。

先说结论：崩溃后请把 GPCL 导出的 错误报告压缩包 发给帮助你的人。
不要发崩溃窗口的截图 —— 截图里没有任何一行有用的日志，只发截图会让排查从零开始。

导出错误报告

崩溃弹窗上就有这个按钮，点「导出错误报告」，选一个位置保存。

  1. GPCL 会把崩溃报告、最新的游戏日志、启动器日志、系统与 Java 信息、启动参数打包成一个 zip。
  2. 把这个 zip 原样发出去，不要从里面挑文件，也不要改名成图片。
  3. 如果游戏还能启动，也可以进「设置 → 关于」页面找到日志目录，手动把 logs 文件夹和 crash-reports 文件夹一起打包。

自己先看一眼日志

弹窗上的「查看日志」会打开内置的日志窗口，里面是游戏进程的真实输出。

  1. 崩溃最关键的信息通常在最底部 —— 那里是游戏关闭前打的最后几行。
  2. 搜 Exception、Caused by、Error 这几个词，第一个真正的异常往往是根因，后面的多半是连锁反应。
  3. 看到 OutOfMemoryError 是内存不够；看到某个 mod 的名字，多半是那个 mod 的问题；看到 Unsupported class file major version 是 Java 版本不对。

常见原因对照

大部分崩溃都落在下面几种里，可以对号入座。

Java 版本不匹配

1.16 及更早需要 Java 8，1.17 之后需要 Java 17，1.20.5 之后需要 Java 21。装错版本游戏会直接闪退。

UnsupportedClassVersionError

内存不足

分配的内存太小，或者模组太多装不下。在「版本设置 → 游戏最大内存」里调大，注意别超过物理内存。

OutOfMemoryError / GC overhead

Mod 冲突或版本不对

Mod 与游戏版本不匹配、两个 Mod 抢同一个功能，或少了前置 Mod，都会在加载阶段崩掉。

NoSuchMethodError / Missing dependency

显卡驱动太旧

驱动过旧或不支持游戏要求的 OpenGL 版本时，窗口还没出现就退出。

GLFW error / Pixel format not accelerated

正版验证失败

正版登录过期，或者账号没有该版本的授权，在线模式进游戏会被服务端拒绝。

Invalid session / Failed to verify username

存档或资源包损坏

世界文件、资源包或光影包损坏，一般崩在加载存档或进入世界的时候。

Failed to load / corrupt

自己先排除的三件事

  1. 先裸启动一次。关掉所有 Mod、资源包和光影，只留原版。裸装能进，就是某个 Mod 的问题。
  2. 换一个版本试。在 GPCL 里下载另一个原版版本启动，确认是不是这个版本本身的问题。
  3. 看是不是只有这张地图崩。新建一个世界能进，就是存档坏了，把存档备份出来再单独处理。

来求助

把错误报告压缩包附上，再写清楚这几件事：游戏版本、装了什么 Mod、崩溃前做了什么操作、是不是每次都能复现。
