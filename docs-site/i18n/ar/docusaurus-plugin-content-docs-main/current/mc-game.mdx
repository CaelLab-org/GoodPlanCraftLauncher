نافذة الانهيار نفسها لا تُظهر السبب عادةً. يقرأ GPCL السجلات أولًا ويعطي مؤشرات، ثم تابع بالترتيب التالي.

:::tip ابدأ بخطوة واحدة
انقر على «تصدير تقرير الخطأ» في نافذة الانهيار واحفظ ملف zip الناتج. تبدأ النتيجة بتحليل GPCL، ثم تأتي قائمة المودات وJava ومعاملات التشغيل وكل السجلات؛ ويعتمد التشخيص عليها في الأساس.
:::

## 1. اطّلع أولًا على تحليل GPCL

تعرض النافذة مؤشرًا أو مؤشرين وجدهما GPCL في السجلات، مثل «الذاكرة غير كافية» أو «لم ينجح فحص متطلبات المودات أو توافقها». وبالنقر على «عرض التفاصيل» ترى كل المؤشرات وأسطر السجل المقابلة ومعلومات الانهيار.

هذه الاستنتاجات مبنية على مطابقة كلمات مفتاحية وتُعد اتجاهًا للبحث فقط. وإذا احتوى السجل على معلومات أدق (مثل المتطلب الناقص) تُضاف إلى الأدلة.

## 2. صدّر تقرير الخطأ

الزر موجود في نافذة الانهيار. اختر موقعًا للحفظ، وسيحزم GPCL:

- `error-report.txt`: نتيجة التحليل وملخص الخطأ والنظام / بطاقة الرسوميات / Java وقائمة المودات وحزم الموارد والشيدرات ومعاملات التشغيل وناتج اللعبة وأسطر الأخطاء في السجل؛
- `crash-reports/`: تقارير الانهيار الناتجة عن هذا الانهيار؛
- `logs/`: الملفان `latest.log` و`debug.log` (وعند كبر الحجم يُحتفظ بالجزء الأخير فقط)؛
- `jvm-crash/`: ملفات `hs_err_pid*.log` التي يكتبها JVM بنفسه (إذا انهار JVM بسبب مشكلة في تعريف بطاقة الرسوميات مثلًا)؛
- `launcher-log.txt`: سجل المشغّل؛
- `game-output.txt`: الخرج القياسي وخرج الأخطاء لعملية اللعبة في هذه الجلسة.

قيم `--accessToken` واسم مستخدم النظام في التقرير مُموّهة، ويمكن إرساله كما هو. لا ترسل لقطة شاشة لنافذة الانهيار وحدها.

## 3. اقرأ السجل بنفسك

«عرض السجل» في النافذة يفتح خرج عملية اللعبة. ركّز على الجزء الأخير وابحث عن هذه الكلمات:

| الكلمة المفتاحية | ما تعنيه عادةً |
| --- | --- |
| `Exception` و`Caused by` | الاستثناء الحقيقي يظهر عادةً بعد أول `Caused by` |
| `OutOfMemoryError` | الذاكرة المخصّصة غير كافية |
| `UnsupportedClassVersionError` | إصدار Java لا يطابق إصدار اللعبة |
| `NoSuchMethodError` و`ClassNotFoundException` | المود لا يطابق إصدار اللعبة أو إصدار المُحمّل، أو المتطلب ناقص |
| `GLFW error` | مشكلة في تعريف بطاقة الرسوميات أو في دعم OpenGL |

## 4. الأسباب الشائعة

| العرض | السبب الشائع | ما تفعله |
| --- | --- | --- |
| يخرج فور التشغيل وفي السجل `UnsupportedClassVersionError` | إصدار Java غير صحيح | دع GPCL يضيف Java تلقائيًا؛ أو غيّر مصدر المرآة في الإعدادات وأعد التثبيت |
| يتوقف أو يغلق فجأة في منتصف التحميل وفي السجل `OutOfMemoryError` | نقص الذاكرة أو كثرة المودات | ارفع القيمة في الإعدادات ← اللعبة ← توزيع الذاكرة؛ لا تتجاوز الذاكرة الفيزيائية |
| ينهار أثناء تحميل المودات ويظهر اسم مود في السجل | إصدار المود غير صحيح أو متطلب ناقص أو تعارض بين مودين | جرّب هذا المود وحده أولًا؛ وتأكد من إصدار MC والمُحمّل المدعومين |
| يخرج قبل ظهور النافذة مع `GLFW error` | تعريف بطاقة الرسوميات قديم أو OpenGL غير مدعوم | حدّث تعريف بطاقة الرسوميات؛ وتأكد في الحاسوب المحمول من أن اللعبة تستخدم البطاقة المنفصلة |
| يُطرد من الخادم مع `Invalid session` | انتهت صلاحية تسجيل الدخول الرسمي أو الحساب لا يملك ترخيص هذا الإصدار | أعد تسجيل الدخول الرسمي؛ وتأكد من ملكية الحساب لهذا الإصدار |
| ينهار عند دخول العالم أو تحميل حزمة موارد | ملف حفظ أو حزمة موارد أو حزمة شيدر تالفة | أنشئ عالمًا جديدًا للتجربة أولًا؛ وخذ نسخة احتياطية من ملفات الحفظ قبل المعالجة |
| ينهار عند التشغيل بـ Fabric مع رسالة نقص `fabric-api` | Fabric API غير مثبّت | أعد تثبيت Fabric مع تحديد «تثبيت Fabric API أيضًا»، أو ثبّته يدويًا |

## 5. استبعد هذه الثلاثة أولًا

1. **أوقف كل المودات وحزم الموارد والشيدرات** وشغّل اللعبة نظيفة مرة واحدة. إذا أقلعت فالمشكلة في المودات.
2. **شغّل إصدارًا أصليًا آخر**. إذا أقلعت فالمشكلة في الإصدار الحالي أو في تركيبة موداته.
3. **أنشئ عالمًا جديدًا**. إذا أقلعت فالملف المحفوظ القديم تالف.

## 6. إذا لم ينفع شيء

أرسل بريدًا إلى [gamets@caellab.com](mailto:gamets@caellab.com) مع تقرير الخطأ المصدّر، واذكر:

- إصدار المشغّل وإصدار Minecraft وإصدار المُحمّل؛
- المودات المثبّتة (مع أرقام الإصدارات إن أمكن)؛
- ما فعلته قبل الانهيار.

وصف «ينهار فور التشغيل» وحده يصعّب التحديد؛ السجلات في التقرير هي المفتاح.
