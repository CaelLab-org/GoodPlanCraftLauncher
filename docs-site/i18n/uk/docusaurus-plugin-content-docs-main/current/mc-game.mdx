Саме вікно збою зазвичай не показує причину. GPCL спершу читає журнали й дає підказки, а далі дійте за наведеним нижче порядком.

:::tip Спершу зробіть одну річ
Натисніть «Експортувати звіт про помилку» у вікні збою й збережіть zip. На початку звіту — результати аналізу GPCL, далі список модів, Java, параметри запуску й усі журнали; діагностика майже завжди спирається на нього.
:::

## 1. Спершу подивіться аналіз GPCL

У вікні показуються 1–2 підказки, які GPCL знайшов у журналах, наприклад «Не вистачає пам'яті» або «Перевірка залежностей чи сумісності модів не пройдена». Натисніть «Докладніше», щоб побачити всі підказки, відповідні рядки журналу й інформацію про збій.

Ці висновки базуються на збігу ключових слів і є лише напрямком для пошуку. Якщо в журналі є точніша інформація (наприклад, якої залежності бракує), вона потрапить до доказів.

## 2. Експортуйте звіт про помилку

Кнопка є в тому ж вікні збою. Виберіть місце для збереження, і GPCL спакує:

- `error-report.txt`: результати аналізу, стислий опис помилки, система / відеокарта / Java, список модів, пакети ресурсів і шейдери, параметри запуску, вивід гри, рядки помилок із журналу;
- `crash-reports/`: звіти про збій, створені цього разу;
- `logs/`: `latest.log` і `debug.log` (якщо завеликі — лише кінець);
- `jvm-crash/`: `hs_err_pid*.log`, які пише сама JVM (якщо JVM падає через драйвер відеокарти тощо);
- `launcher-log.txt`: журнал лаунчера;
- `game-output.txt`: стандартний вивід і вивід помилок процесу гри за цей запуск.

`--accessToken` і системне ім'я користувача у звіті замасковані, тому його можна надсилати як є. Не надсилайте лише скріншот вікна збою.

## 3. Подивіться журнал самі

«Переглянути журнал» у вікні відкриває вивід процесу гри. Дивіться на найнижчу частину й пошукайте ці слова:

| Ключове слово | Зазвичай означає |
| --- | --- |
| `Exception`, `Caused by` | Справжній виняток зазвичай після першого `Caused by` |
| `OutOfMemoryError` | Виділеної пам'яті не вистачає |
| `UnsupportedClassVersionError` | Версія Java не відповідає версії гри |
| `NoSuchMethodError`, `ClassNotFoundException` | Мод не збігається з версією гри чи завантажувача або бракує залежності |
| `GLFW error` | Проблема з драйвером відеокарти або підтримкою OpenGL |

## 4. Типові причини

| Симптом | Типова причина | Що робити |
| --- | --- | --- |
| Одразу виходить після запуску, у журналі `UnsupportedClassVersionError` | Неправильна версія Java | Дозвольте GPCL додати Java автоматично; або змініть дзеркало в налаштуваннях і перевстановіть |
| Зависає чи вилітає під час завантаження, у журналі `OutOfMemoryError` | Не вистачає пам'яті або забагато модів | Збільште в Налаштування → Гра → Розподіл пам'яті; не перевищуйте фізичну пам'ять |
| Падає під час завантаження модів, у журналі є назва мода | Неправильна версія мода, бракує залежності, конфлікт двох модів | Спершу залиште лише цей мод; перевірте підтримувані версії MC і завантажувача |
| Виходить до появи вікна, є `GLFW error` | Застарий драйвер відеокарти або немає підтримки OpenGL | Оновіть драйвер; на ноутбуці переконайтеся, що гра йде через дискретну відеокарту |
| Викидає з сервера з `Invalid session` | Прострочений ліцензійний вхід або в акаунта немає прав на цю версію | Увійдіть ліцензійно знову; переконайтеся, що акаунт володіє цією версією |
| Падає при вході у світ або завантаженні пакета ресурсів | Пошкоджене збереження, пакет ресурсів або шейдер | Спершу створіть новий світ; зробіть резервну копію збережень і тоді розбирайтеся |
| Падає на Fabric із повідомленням про відсутній `fabric-api` | Не встановлено Fabric API | Перевстановіть Fabric з позначкою «Також встановити Fabric API» або поставте його вручну |

## 5. Спершу виключіть ці три речі

1. **Вимкніть усі моди, пакети ресурсів і шейдери** та запустіть гру начисто. Якщо запускається — проблема в модах.
2. **Запустіть іншу оригінальну версію**. Якщо запускається — проблема в поточній версії або наборі її модів.
3. **Створіть новий світ**. Якщо запускається — пошкоджене старе збереження.

## 6. Якщо нічого не допомогло

Напишіть на [gamets@caellab.com](mailto:gamets@caellab.com), додайте експортований звіт про помилку і вкажіть:

- версію лаунчера, версію Minecraft, версію завантажувача;
- які моди встановлені (бажано з версіями);
- що робили перед збоєм.

Опис «падає одразу після запуску» майже не допомагає локалізувати проблему — ключ саме в журналах звіту.
