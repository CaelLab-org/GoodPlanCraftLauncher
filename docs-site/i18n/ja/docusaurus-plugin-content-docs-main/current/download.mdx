ダウンロードが遅いのは、たいていランチャーのせいではありません。まずダウンロード元を変え、そのうえでスレッド数と速度制限を検討してください。

## ダウンロードはキューに入る

「ダウンロード」を押すとタスクはキューに入り、画面全体が固まることはありません。待機中のタスクは × で削除でき、実行中のタスクはキャンセルでき、キャンセル後もキューは続行します。

ダウンロードページには各タスクの状態（待機中、ダウンロード中、完了、失敗）が表示されます。

## ファイルの取得元とバージョン一覧の取得元

**設定 → ダウンロード → ダウンロード元** には独立した 2 つのドロップダウンがあります。

- **ファイルのダウンロード元**：クライアント jar、アセット、依存ライブラリ
- **バージョン一覧の取得元**：バージョンマニフェスト、バージョン JSON、アセットインデックス

どちらも同じ 4 つの選択肢です。

| 選択肢 | 動作 |
| --- | --- |
| 公式を優先し、遅いときはミラー | 既定。まず公式に接続し、数秒応答がなければ BMCLAPI に切り替え |
| ミラーを優先 | 中国本土のネットワークではミラーを直接使用 |
| 公式を優先 | まず公式、失敗したらミラーに戻る |
| 公式のみ | 公式のみ使用。公式に接続できなければ失敗 |

## カスタムファイルミラー

**設定 → ダウンロード → カスタムファイルミラー** にはミラーのルートアドレスを入力できます（既定は BMCLAPI、例：`https://bmclapi2.bangbang93.com`）。入力すると、バージョンマニフェスト、クライアント、ライブラリ、アセットがまずそこを使い、取得できなければ通常の取得元の順序でフォールバックします。

空欄なら既定の BMCLAPI です。

## ゲームディレクトリ

**設定 → ダウンロード → ゲームディレクトリ** で、バージョン、ライブラリ、アセット、Mod を任意のフォルダーに置けます。空欄なら `%APPDATA%\gpcl\.minecraft` に戻ります。

ディレクトリを切り替えても既存のファイルは**自動で移動しません**。元のディレクトリのバージョンは付いてこないため、必要なら自分でコピーしてください。設定とログは引き続き `%APPDATA%\gpcl` にあります。

## 最大スレッド数

既定は 64、範囲は 1-128 です。小さいファイルが多いときは並列度を上げると速くなりますが、上げすぎるとネットワーク機器やミラー側の制限に当たることがあります。回線が不安定なときは下げてください。

## 速度制限

0 は無制限です。値を入れると、**すべてのダウンロードがこの合計上限を共有**します。単位は MB/s で、次回のダウンロード開始時から有効です。回線を複数人で共有している場合は下げてください。

この制限はゲームのアセットのダウンロードだけに適用されます。Java ランタイムは別のミラーから取得するため、ここには影響しません。

## Java ミラー

**設定 → ダウンロード → Java のダウンロード** では、清華大学、南京大学、Huawei Cloud、カスタムから選べます。選択した取得元が失敗すると自動で次に切り替わり、最後は Adoptium 公式が受け止めます。

カスタムアドレスでは 2 つの変数が使えます。

- `{v}`：Java のメジャーバージョン（例：`8`、`17`、`21`）
- `{version}`：上流の完全なバージョン番号（例：`17.0.20.1_1`）。上流のリリースに合わせて変わります。

例：

```text
https://cdn.example.com/java/{v}/OpenJDK{v}U-jre_x64_windows_hotspot_{v}.zip
```

## ダウンロードに失敗したら

1. 別のダウンロード元に切り替える。
2. スレッド数を 32 か 16 に下げて再試行する。
3. システムの時刻が正しいか確認する。大きくずれていると HTTPS 証明書の検証に失敗します。
4. それでもだめなら、`%APPDATA%\gpcl\gpcl\log` の最新ログを添えてメールしてください。
