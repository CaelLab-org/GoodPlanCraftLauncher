---
title: Java とメモリ
description: Java のバージョンの対応関係、GPCL のメモリ自動割り当て、メモリ不足時の調整方法。
---

GPCL はゲームのバージョンに合わせて Java を自動で選び、PC のメモリに応じて自動で割り当てます。ほとんどの場合、手動で変更する必要はありません。

## Java のバージョン対応

| Minecraft のバージョン | 必要な Java |
| --- | --- |
| 1.16.5 以前 | Java 8 |
| 1.17 - 1.20.4 | Java 17 |
| 1.20.5 以降 | Java 21 |

起動時に対応する Java がない場合、GPCL が自動でダウンロードしてインストールします。ダウンロードに失敗する場合は、**設定 → ダウンロード → Java のダウンロード** でミラーを変えて再試行してください。

Java は GPCL 専用のディレクトリにインストールされ、システム上の他の Java には影響しません。システムの `JAVA_HOME` も変更しません。

## メモリ：自動

既定は「自動」です。割り当ては 2 段階で決まります。

1. まず物理メモリの **30%** を見積もり、GB 単位で切り捨て、**2 - 8 GB** に収めます。
2. 次に現在の空きメモリを見ます。システム用に最低 1 GB を残し、下限は 2 GB とし、結果を 512 MB 単位で切り捨て、2 つのうち小さいほうを採用します。

実際の結果の例：

| 物理メモリ | 現在の空き | 自動割り当て |
| --- | --- | --- |
| 16 GB | 8 GB | 4 GB |
| 16 GB | 3.9 GB | 2.5 GB |
| 8 GB | 4 GB | 2 GB |

設定ページにはシステムメモリの使用量 / 合計と現在の空きが表示されます。空きが厳しいときは自動割り当てが下がり、いくつかのプログラムを閉じるよう促します。

`-Xmx` は上限であり、起動と同時に使い切るものではありません。その場の空きメモリに合わせて割り当てるほうが、無理に大きな値を与えるより安定します。

## メモリ：カスタム

Mod パックや大型の Mod 構成で足りない場合は「カスタム」に切り替えてスライダーを動かします。システムや他のプログラムの分を残し、物理メモリをすべてゲームに与えないでください。

`OutOfMemoryError` が出たらメモリ不足です。

1. 割り当てを 1 段階上げて再試行する
2. それでもだめなら Mod を減らす
3. ブラウザーなどメモリを使うプログラムも同時に閉じる

## G1GC のチューニング

**設定 → 詳細設定 → メモリ管理** に G1GC のチューニングがあり、既定ではオフです。フレームレートの変動や GC による引っかかりが目立つ場合にのみオンにすることを勧めます。オンにすると一般的な G1GC の引数一式が追加されます。

カスタム JVM 引数も同じ場所にあります。引数を誤るとゲームが起動しなくなるため、自信がない場合は変更しないでください。

## 起動前のメモリ最適化

オンにすると、GPCL はゲーム起動前に自身が使っているメモリの一部を解放します。対象はランチャー自身のプロセスだけで、実行中の Minecraft には触れず、ログイン状態も消しません。

ハードディスクではこの処理で一瞬引っかかることがありますが、正常な動作です。
