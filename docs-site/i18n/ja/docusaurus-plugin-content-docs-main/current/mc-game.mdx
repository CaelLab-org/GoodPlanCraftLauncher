クラッシュ画面そのものから原因が分かることは、ほとんどありません。GPCL がまずログを読んで手がかりを出し、そのうえで次の順に切り分けます。

:::tip まず 1 つだけ
クラッシュダイアログの「エラーレポートを書き出す」を押し、生成された zip を保存してください。レポートの冒頭が GPCL の分析結果で、その後に Mod 一覧、Java、起動引数、すべてのログが続きます。切り分けはほぼこれが頼りです。
:::

## 1. まず GPCL の分析を見る

ダイアログには、GPCL がログから見つけた手がかりが 1-2 件表示されます（例：「メモリ不足」「Mod の依存関係または互換性のチェックに通りませんでした」）。「詳細を表示」を押すと、すべての手がかり、対応するログの原文、クラッシュ情報を確認できます。

これらの結論はキーワード照合によるもので、切り分けの方向としてだけ使ってください。ログにもっと具体的な情報がある場合（足りない前提 Mod など）は、根拠の欄にも併記されます。

## 2. エラーレポートを書き出す

クラッシュダイアログにボタンがあります。保存先を選ぶと、GPCL は次の内容をまとめます。

- `error-report.txt`：分析結果、エラー概要、システム / GPU / Java、Mod 一覧、リソースパックとシェーダー、起動引数、ゲーム出力、ログ内のエラー行
- `crash-reports/`：今回のクラッシュで生成されたクラッシュレポート
- `logs/`：`latest.log` と `debug.log`（大きすぎる場合は末尾のみ）
- `jvm-crash/`：JVM 自身が書き出した `hs_err_pid*.log`（GPU ドライバーなどの問題で JVM がクラッシュした場合）
- `launcher-log.txt`：ランチャーのログ
- `game-output.txt`：今回のゲームプロセスの標準出力と標準エラー出力

レポート内の `--accessToken` とシステムのユーザー名は伏せ字になっているため、そのまま送れます。クラッシュ画面のスクリーンショットだけは送らないでください。

## 3. 自分でログを見る

ダイアログの「ログを表示」でゲームプロセスの出力が開きます。最下部を中心に、次の語句を検索してください。

| キーワード | 通常の意味 |
| --- | --- |
| `Exception`、`Caused by` | 実際の例外は最初の `Caused by` の後ろにあることが多い |
| `OutOfMemoryError` | 割り当てたメモリが足りない |
| `UnsupportedClassVersionError` | Java のバージョンとゲームのバージョンが合っていない |
| `NoSuchMethodError`、`ClassNotFoundException` | Mod とゲーム、またはローダーのバージョンが合っていない、もしくは前提 Mod が足りない |
| `GLFW error` | GPU ドライバーか OpenGL 対応に問題がある |

## 4. よくある原因

| 症状 | よくある原因 | 対処 |
| --- | --- | --- |
| 起動直後に終了し、ログに `UnsupportedClassVersionError` がある | Java のバージョンが違う | GPCL に Java を自動で補わせる。または設定でミラーを変えて再インストールする |
| 読み込みの途中で固まる、または落ち、ログに `OutOfMemoryError` がある | メモリ不足、または Mod が多すぎる | 設定 → ゲーム → メモリ割り当てで増やす。物理メモリは超えない |
| Mod の読み込み中にクラッシュし、ログに Mod 名が出る | Mod のバージョン違い、前提 Mod の不足、2 つの Mod の衝突 | まずその Mod だけを入れて試す。対応する MC バージョンとローダーのバージョンを確認する |
| ウィンドウが出る前に終了し、`GLFW error` がある | GPU ドライバーが古い、または OpenGL 非対応 | GPU ドライバーを更新する。ノート PC ではゲームが専用 GPU を使っているか確認する |
| サーバーに入るとキックされ、`Invalid session` と表示される | 正規アカウントのログインが失効、またはアカウントにこのバージョンの権利がない | 正規アカウントでログインし直す。アカウントがそのバージョンを所有しているか確認する |
| ワールドに入る、またはリソースパックの読み込みでクラッシュする | ワールド、リソースパック、シェーダーパックの破損 | まず新しいワールドで試す。ワールドをバックアップしてから対処する |
| Fabric で起動するとクラッシュし、`fabric-api` の不足が表示される | Fabric API が入っていない | Fabric を入れ直すときに「Fabric API も同時にインストール」にチェックする、または手動で入れる |

## 5. まず次の 3 つを除外する

1. **Mod、リソースパック、シェーダーをすべて外して**、素の状態で 1 回起動する。起動できれば Mod 側の問題です。
2. **バニラのバージョンで起動する。** 起動できれば、現在のバージョンかその Mod 構成に問題があります。
3. **新しいワールドを作る。** 起動できれば、元のワールドが壊れています。

## 6. それでも解決しない場合

[gamets@caellab.com](mailto:gamets@caellab.com) に、書き出したエラーレポートを添えてメールし、次の点も書いてください。

- ランチャーのバージョン、Minecraft のバージョン、ローダーのバージョン
- 導入している Mod（バージョン番号があるとなお良い）
- クラッシュ前に何をしたか

「起動するとすぐ落ちる」だけでは特定が難しく、レポート内のログが鍵になります。
