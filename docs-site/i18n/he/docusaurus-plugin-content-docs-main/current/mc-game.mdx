מחלון הקריסה עצמו בדרך כלל לא רואים את הסיבה. GPCL קורא קודם את הלוגים ונותן רמזים, ואחר כך בודקים לפי הסדר שלמטה.

:::tip דבר אחד קודם
לחצו על "ייצוא דוח שגיאה" בחלון הקריסה ושמרו את קובץ ה-zip. בראש הדוח מופיעות תוצאות הניתוח של GPCL, ואחריהן רשימת המודים, Java, פרמטרי ההפעלה וכל הלוגים — על זה מבוססת רוב הבדיקה.
:::

## 1. קודם תוצאות הניתוח של GPCL

החלון מציג 1–2 רמזים שמצא GPCL בלוגים, למשל "אין מספיק זיכרון" או "בדיקת התלויות או התאימות של המודים לא עברה". לחיצה על "הצג פרטים" מציגה את כל הרמזים, את שורות הלוג המתאימות ואת פרטי הקריסה.

המסקנות מבוססות על התאמת מילות מפתח, ולכן אפשר להשתמש בהן רק ככיוון לבדיקה. כשיש בלוג מידע מדויק יותר (למשל איזו תלות חסרה), הוא מופיע בראיות.

## 2. ייצוא דוח שגיאה

הכפתור נמצא בחלון הקריסה עצמו. בוחרים מקום לשמירה, ו-GPCL אורז:

- `error-report.txt`: תוצאות הניתוח, תקציר השגיאה, מערכת / כרטיס גרפי / Java, רשימת המודים, חבילות משאבים ושיידרים, פרמטרי הפעלה, פלט המשחק ושורות השגיאה מהלוג;
- `crash-reports/`: דוח הקריסה שנוצר בהפעלה הזו;
- `logs/`: `latest.log` ו-`debug.log` (אם גדולים מדי — רק החלק האחרון);
- `jvm-crash/`: קובץ `hs_err_pid*.log` שכותב ה-JVM (אם בעיה כמו דרייבר כרטיס גרפי מפילה את ה-JVM);
- `launcher-log.txt`: הלוג של המשגר;
- `game-output.txt`: הפלט הרגיל ופלט השגיאות של תהליך המשחק בהרצה הזו.

הדוח כבר מטשטש את `--accessToken` ואת שם המשתמש של המערכת, ואפשר לשלוח אותו כמו שהוא. אל תשלחו רק צילום מסך של חלון הקריסה.

## 3. קריאת הלוג בעצמכם

"הצג לוג" בחלון פותח את הפלט של תהליך המשחק. שימו לב לתחתית, וחפשו את המילים האלה:

| מילת מפתח | מה היא בדרך כלל אומרת |
| --- | --- |
| `Exception`, `Caused by` | החריגה האמיתית נמצאת בדרך כלל אחרי ה-`Caused by` הראשון |
| `OutOfMemoryError` | הזיכרון שהוקצה לא מספיק |
| `UnsupportedClassVersionError` | גרסת ה-Java לא תואמת לגרסת המשחק |
| `NoSuchMethodError`, `ClassNotFoundException` | אי-התאמה בין המוד לגרסת המשחק או הלואדר, או תלות חסרה |
| `GLFW error` | בעיה בדרייבר כרטיס גרפי או בתמיכת OpenGL |

## 4. סיבות נפוצות

| תסמין | סיבה נפוצה | מה לעשות |
| --- | --- | --- |
| נסגר מיד בהפעלה, ובלוג יש `UnsupportedClassVersionError` | גרסת Java לא נכונה | לתת ל-GPCL להתקין את ה-Java המתאים; או לשנות מקור מירור בהגדרות ולהתקין מחדש |
| נתקע או נסגר באמצע הטעינה, ובלוג יש `OutOfMemoryError` | אין מספיק זיכרון, או יותר מדי מודים | הגדרות → משחק → הקצאת זיכרון — להעלות; לא לעבור את הזיכרון הפיזי |
| קורס בזמן טעינת מודים, ובלוג מופיע שם המוד | גרסת מוד לא נכונה, תלות חסרה, שני מודים מתנגשים | קודם להתקין רק את המוד הזה ולנסות; לוודא אילו גרסאות MC ולואדר הוא תומך בהן |
| יוצא עוד לפני שהחלון מופיע, עם `GLFW error` | דרייבר כרטיס גרפי ישן מדי, או אין תמיכת OpenGL | לעדכן את הדרייבר; במחשב נייד לוודא שהמשחק רץ על הכרטיס הגרפי הנפרד |
| נזרקים מהשרת עם `Invalid session` | התחברות הפרימיום פגה, או שלחשבון אין הרשאה לגרסה | להתחבר שוב עם חשבון פרימיום; לוודא שלחשבון באמת יש את הגרסה |
| קורס בכניסה לעולם או בטעינת חבילת משאבים | עולם שמור, חבילת משאבים או חבילת שיידרים פגומים | קודם ליצור עולם חדש ולנסות; לגבות את העולמות השמורים ואז לטפל |
| קורס בהפעלה עם Fabric ומופיעה הודעה שחסר `fabric-api` | Fabric API לא מותקן | להתקין שוב את Fabric עם הסימון "התקנת Fabric API יחד עם Fabric", או להתקין ידנית |

## 5. שלוש בדיקות שמוציאות הכי הרבה

1. **לכבות את כל המודים, חבילות המשאבים והשיידרים** ולהפעיל פעם אחת בלי כלום. אם עולה — הבעיה במודים.
2. **להפעיל גרסת וניל אחרת**. אם עולה — הבעיה בגרסה הנוכחית או בשילוב המודים שלה.
3. **ליצור עולם חדש**. אם עולה — העולם השמור הקודם פגום.
