GPCL은 게임 버전에 맞춰 Java를 자동으로 고르고, PC 메모리에 따라 자동으로 할당합니다. 대부분의 경우 직접 바꿀 필요가 없습니다.

## Java 버전 대응

| Minecraft 버전 | 필요한 Java |
| --- | --- |
| 1.16.5 이하 | Java 8 |
| 1.17 - 1.20.4 | Java 17 |
| 1.20.5 이상 | Java 21 |

실행할 때 해당 Java가 없으면 GPCL이 자동으로 내려받아 설치합니다. 다운로드에 실패하면 **설정 → 다운로드 → Java 다운로드**에서 미러를 바꿔 다시 시도하세요.

Java는 GPCL 전용 폴더에 설치되며, 시스템의 다른 Java에 영향을 주지 않고 시스템 `JAVA_HOME`도 바꾸지 않습니다.

## 메모리: 자동

기본값은 "자동"입니다. 할당은 두 단계로 정해집니다.

1. 먼저 물리 메모리의 **30%**로 추정하고 GB 단위로 내림한 뒤 **2 - 8 GB** 범위로 제한합니다.
2. 다음으로 현재 사용 가능한 메모리를 봅니다. 시스템에 최소 1 GB를 남기고, 하한은 2 GB로 잡고, 결과를 512 MB 단위로 내림한 뒤 둘 중 작은 값을 씁니다.

실제 결과 몇 가지:

| 물리 메모리 | 현재 사용 가능 | 자동 할당 |
| --- | --- | --- |
| 16 GB | 8 GB | 4 GB |
| 16 GB | 3.9 GB | 2.5 GB |
| 8 GB | 4 GB | 2 GB |

설정 페이지에는 시스템 메모리의 사용량 / 전체와 현재 사용 가능한 값이 표시됩니다. 사용 가능한 메모리가 빠듯하면 자동 할당이 함께 내려가고, 프로그램 몇 개를 먼저 닫으라고 안내합니다.

`-Xmx`는 상한이며 실행하자마자 모두 차지하는 값이 아닙니다. 그래서 그때의 사용 가능한 메모리에 맞춰 할당하는 편이 큰 값을 억지로 주는 것보다 안정적입니다.

## 메모리: 사용자 지정

모드팩이나 대형 모드 구성에서 부족하면 "사용자 지정"으로 바꾸고 슬라이더를 움직이세요. 시스템과 다른 프로그램을 위한 공간을 남기고, 물리 메모리를 전부 게임에 주지 마세요.

`OutOfMemoryError`가 나오면 메모리가 부족한 것입니다.

1. 할당을 한 단계 올려 다시 시도합니다.
2. 그래도 안 되면 모드를 줄입니다.
3. 브라우저처럼 메모리를 많이 쓰는 프로그램도 함께 닫습니다.

## G1GC 튜닝

**설정 → 고급 → 메모리 관리**에 G1GC 튜닝이 있고 기본값은 꺼짐입니다. 프레임이 흔들리거나 GC로 인한 끊김이 뚜렷할 때만 켜는 것을 권합니다. 켜면 일반적으로 쓰이는 G1GC 인수 묶음이 추가됩니다.

사용자 지정 JVM 인수도 같은 위치에 있습니다. 인수를 잘못 쓰면 게임이 아예 시작되지 않으므로, 확실하지 않으면 바꾸지 마세요.

## 실행 전 메모리 최적화

켜면 GPCL이 게임을 실행하기 전에 자신이 쓰는 메모리 일부를 회수합니다. 런처 자체 프로세스만 정리하며, 실행 중인 Minecraft를 건드리지 않고 로그인 상태도 지우지 않습니다.

하드디스크에서는 이 단계에서 잠깐 끊길 수 있으며 정상 동작입니다.
