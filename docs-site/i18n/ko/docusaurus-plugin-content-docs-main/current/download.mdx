다운로드가 느린 것은 대개 런처의 문제가 아닙니다. 먼저 다운로드 소스를 바꾸고, 그다음 스레드 수와 속도 제한을 보세요.

## 다운로드 작업은 대기열에 들어갑니다

"다운로드"를 누르면 작업이 대기열에 들어가 화면 전체가 멈추지 않습니다. 대기 중인 작업은 ×로 제거할 수 있고, 진행 중인 작업은 취소할 수 있으며, 취소해도 대기열은 계속 진행됩니다.

다운로드 페이지에는 각 작업의 상태(대기 중, 다운로드 중, 완료, 실패)가 표시됩니다.

## 파일 소스와 버전 목록 소스

**설정 → 다운로드 → 다운로드 소스**에는 서로 독립적인 드롭다운 두 개가 있습니다.

- **파일 다운로드 소스**: 클라이언트 jar, 에셋, 의존 라이브러리
- **버전 목록 소스**: 버전 매니페스트, 버전 JSON, 에셋 인덱스

둘 다 같은 네 가지 옵션을 제공합니다.

| 옵션 | 동작 |
| --- | --- |
| 공식 우선, 느리면 미러 | 기본값. 먼저 공식에 연결하고 몇 초간 응답이 없으면 BMCLAPI로 전환 |
| 미러 우선 | 중국 본토 네트워크에서는 미러를 바로 사용 |
| 공식 우선 사용 | 먼저 공식, 실패하면 미러로 대체 |
| 공식만 사용 | 공식만 사용하고, 연결할 수 없으면 실패 |

## 사용자 지정 파일 미러

**설정 → 다운로드 → 사용자 지정 파일 미러**에 미러 루트 주소를 넣을 수 있습니다(기본값 BMCLAPI, 예: `https://bmclapi2.bangbang93.com`). 넣으면 버전 매니페스트, 클라이언트, 라이브러리, 에셋이 먼저 이 주소를 쓰고, 가져오지 못하면 원래 소스 순서로 대체합니다.

비워 두면 기본 BMCLAPI입니다.

## 게임 폴더

**설정 → 다운로드 → 게임 폴더**에서 버전, 라이브러리, 에셋, 모드를 임의의 폴더에 둘 수 있습니다. 비워 두면 `%APPDATA%\gpcl\.minecraft`로 돌아갑니다.

폴더를 바꿔도 기존 파일은 **자동으로 옮겨지지 않습니다**. 이전 폴더의 버전은 따라오지 않으므로 필요하면 직접 복사하세요. 설정과 로그는 여전히 `%APPDATA%\gpcl`에 있습니다.

## 최대 스레드 수

기본값 64, 범위 1-128입니다. 작은 파일이 많을 때 동시성을 높이면 빨라지지만, 너무 높으면 네트워크 장비나 미러의 제한에 걸릴 수 있습니다. 네트워크가 불안정하면 낮추세요.

## 속도 제한

0은 제한 없음입니다. 값을 넣으면 **모든 다운로드 작업이 이 총 상한을 공유**하며, 단위는 MB/s이고 다음 다운로드가 시작될 때 적용됩니다. 여러 사람이 네트워크를 함께 쓸 때 낮추면 됩니다.

이 제한은 게임 에셋 다운로드에만 적용됩니다. Java 런타임은 별도 미러에서 받으므로 여기에 영향을 받지 않습니다.

## Java 미러

**설정 → 다운로드 → Java 다운로드**에서 칭화대, 난징대, 화웨이 클라우드, 사용자 지정 중에 고를 수 있습니다. 선택한 소스가 실패하면 자동으로 다음 소스로 넘어가고, 마지막은 Adoptium 공식이 받쳐 줍니다.

사용자 지정 주소는 두 가지 변수를 지원합니다.

- `{v}`: Java 주 버전(예: `8`, `17`, `21`)
- `{version}`: 업스트림 전체 버전 번호(예: `17.0.20.1_1`)로, 업스트림 릴리스에 따라 바뀝니다.

예:

```text
https://cdn.example.com/java/{v}/OpenJDK{v}U-jre_x64_windows_hotspot_{v}.zip
```

## 다운로드가 실패하면

1. 다른 다운로드 소스로 바꿉니다.
2. 스레드 수를 32 또는 16으로 낮춰 다시 시도합니다.
3. 시스템 시간이 맞는지 확인합니다. 시간 오차가 크면 HTTPS 인증서 검증이 실패합니다.
4. 그래도 안 되면 `%APPDATA%\gpcl\gpcl\log`의 최신 로그를 첨부해 메일을 보내세요.
