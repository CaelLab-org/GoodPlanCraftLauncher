충돌 창만 봐서는 원인을 알기 어려운 경우가 대부분입니다. GPCL이 먼저 로그를 읽어 단서를 내고, 그다음 아래 순서로 확인합니다.

:::tip 먼저 한 가지
충돌 창의 "오류 보고서 내보내기"를 눌러 생성된 zip을 저장하세요. 보고서 앞부분이 GPCL의 분석 결과이고, 뒤이어 모드 목록, Java, 실행 인수, 모든 로그가 담깁니다. 점검은 대부분 이것에 기대게 됩니다.
:::

## 1. 먼저 GPCL의 분석 보기

창에는 GPCL이 로그에서 찾은 단서 1-2개가 표시됩니다(예: "메모리 부족", "모드 의존성 또는 호환성 검사에 통과하지 못함"). "자세히 보기"를 누르면 모든 단서, 해당 로그 원문, 충돌 정보를 볼 수 있습니다.

이 결론은 키워드 매칭으로 나온 것이라 점검 방향으로만 쓰세요. 로그에 더 구체적인 정보가 있으면(어떤 선행 모드가 빠졌는지 등) 근거 항목에 함께 적힙니다.

## 2. 오류 보고서 내보내기

충돌 창에 이 버튼이 있습니다. 위치를 골라 저장하면 GPCL이 다음을 묶습니다.

- `error-report.txt`: 분석 결과, 오류 요약, 시스템 / 그래픽 카드 / Java, 모드 목록, 리소스 팩과 셰이더, 실행 인수, 게임 출력, 로그의 오류 줄
- `crash-reports/`: 이번 충돌로 생성된 크래시 보고서
- `logs/`: `latest.log`와 `debug.log`(너무 크면 끝부분만 유지)
- `jvm-crash/`: JVM이 직접 기록한 `hs_err_pid*.log`(그래픽 카드 드라이버 등의 문제로 JVM이 충돌한 경우)
- `launcher-log.txt`: 런처 로그
- `game-output.txt`: 이번 게임 프로세스의 표준 출력과 표준 오류

보고서의 `--accessToken`과 시스템 사용자 이름은 가려져 있어 그대로 보내도 됩니다. 충돌 창 스크린샷만 보내지 마세요.

## 3. 로그를 직접 보기

창의 "로그 보기"는 게임 프로세스의 출력을 엽니다. 맨 아래쪽을 중심으로 다음 단어를 검색하세요.

| 키워드 | 보통 의미하는 것 |
| --- | --- |
| `Exception`, `Caused by` | 실제 예외는 대개 첫 번째 `Caused by` 뒤에 있음 |
| `OutOfMemoryError` | 할당한 메모리가 부족함 |
| `UnsupportedClassVersionError` | Java 버전과 게임 버전이 맞지 않음 |
| `NoSuchMethodError`, `ClassNotFoundException` | 모드와 게임 또는 로더 버전이 맞지 않거나 선행 모드가 빠짐 |
| `GLFW error` | 그래픽 카드 드라이버나 OpenGL 지원에 문제가 있음 |

## 4. 흔한 원인

| 증상 | 흔한 원인 | 대처 |
| --- | --- | --- |
| 실행하자마자 종료되고 로그에 `UnsupportedClassVersionError`가 있음 | Java 버전이 다름 | GPCL이 Java를 자동으로 설치하게 하거나, 설정에서 미러를 바꾼 뒤 다시 설치 |
| 로딩 도중 멈추거나 튕기고 로그에 `OutOfMemoryError`가 있음 | 메모리 부족 또는 모드가 너무 많음 | 설정 → 게임 → 메모리 할당에서 늘리기; 물리 메모리를 넘지 말 것 |
| 모드를 불러오다 충돌하고 로그에 모드 이름이 나옴 | 모드 버전이 다름, 선행 모드 누락, 두 모드의 충돌 | 먼저 그 모드만 설치해 시험; 지원하는 MC 버전과 로더 버전 확인 |
| 창이 뜨기 전에 종료되고 `GLFW error`가 있음 | 그래픽 카드 드라이버가 오래되었거나 OpenGL 미지원 | 그래픽 카드 드라이버 업데이트; 노트북이면 게임이 외장 GPU를 쓰는지 확인 |
| 서버에 들어가면 추방되고 `Invalid session`이 표시됨 | 정품 로그인 만료 또는 계정에 이 버전의 권한이 없음 | 정품으로 다시 로그인; 계정이 해당 버전을 보유했는지 확인 |
| 월드에 들어가거나 리소스 팩을 불러올 때 충돌 | 월드, 리소스 팩, 셰이더 팩 손상 | 먼저 새 월드로 시험; 월드를 백업한 뒤 처리 |
| Fabric으로 실행하면 충돌하고 `fabric-api` 누락이 표시됨 | Fabric API가 설치되지 않음 | Fabric을 다시 설치할 때 "Fabric API도 함께 설치"를 체크하거나 직접 설치 |

## 5. 먼저 이 세 가지를 배제하기

1. **모든 모드, 리소스 팩, 셰이더를 끄고** 아무것도 없는 상태로 한 번 실행합니다. 실행되면 모드 쪽 문제입니다.
2. **바닐라 버전으로 실행합니다.** 실행되면 현재 버전이나 그 모드 조합에 문제가 있습니다.
3. **새 월드를 만듭니다.** 실행되면 기존 월드가 손상된 것입니다.

## 6. 그래도 안 되면

[gamets@caellab.com](mailto:gamets@caellab.com)으로 내보낸 오류 보고서를 첨부해 메일을 보내고, 다음도 적어 주세요.

- 런처 버전, Minecraft 버전, 로더 버전
- 설치한 모드(버전 번호가 있으면 더 좋음)
- 충돌 직전에 한 일

"실행하자마자 충돌한다"는 설명만으로는 원인을 찾기 어렵고, 보고서의 로그가 핵심입니다.
