क्रैश विंडो से अक्सर वजह पता नहीं चलती। GPCL पहले लॉग पढ़कर संकेत देता है, फिर नीचे दिए क्रम से जाँचें।

:::tip पहले एक काम
क्रैश डायलॉग पर "एरर रिपोर्ट एक्सपोर्ट करें" क्लिक करें और बनी हुई zip सेव करें। रिपोर्ट के शुरू में GPCL का विश्लेषण होता है, और आगे Mod सूची, Java, लॉन्च पैरामीटर तथा सारे लॉग — जाँच मुख्यतः इसी पर टिकी है।
:::

## 1. पहले GPCL का विश्लेषण देखें

डायलॉग GPCL को लॉग में मिले 1–2 संकेत दिखाता है, जैसे "मेमोरी कम है" या "Mod की डिपेंडेंसी या कम्पैटिबिलिटी जाँच पास नहीं हुई"। "विवरण देखें" पर क्लिक करने से सारे संकेत, उनसे जुड़ी लॉग लाइनें और क्रैश की जानकारी दिखती है।

ये नतीजे कीवर्ड मिलान से निकलते हैं, इसलिए इन्हें सिर्फ़ जाँच की दिशा मानें। जब लॉग में ज़्यादा ठोस जानकारी हो (जैसे कौन-सी डिपेंडेंसी छूटी है), वह सबूतों में साथ दिखाई जाती है।

## 2. एरर रिपोर्ट एक्सपोर्ट करें

बटन क्रैश डायलॉग पर ही है। जगह चुनकर सेव करें, GPCL इन्हें पैक करता है:

- `error-report.txt`: विश्लेषण नतीजे, एरर सारांश, सिस्टम / GPU / Java, Mod सूची, रिसोर्स पैक और शेडर, लॉन्च पैरामीटर, गेम आउटपुट, लॉग की एरर लाइनें;
- `crash-reports/`: इस क्रैश में बनी क्रैश रिपोर्ट;
- `logs/`: `latest.log` और `debug.log` (बहुत बड़ा हो तो सिर्फ़ आखिरी हिस्सा);
- `jvm-crash/`: JVM का खुद लिखा `hs_err_pid*.log` (अगर GPU ड्राइवर जैसी समस्या से JVM क्रैश हो);
- `launcher-log.txt`: लॉन्चर का लॉग;
- `game-output.txt`: इस रन में गेम प्रोसेस का स्टैंडर्ड आउटपुट और एरर आउटपुट।

रिपोर्ट में `--accessToken` और सिस्टम यूज़रनेम पहले से मास्क हैं, इसे सीधे भेजा जा सकता है। सिर्फ़ क्रैश विंडो का स्क्रीनशॉट न भेजें।

## 3. खुद लॉग देखें

डायलॉग का "लॉग देखें" गेम प्रोसेस का आउटपुट खोलता है। सबसे नीचे और इन शब्दों पर ध्यान दें:

| कीवर्ड | आम तौर पर मतलब |
| --- | --- |
| `Exception`, `Caused by` | असली अपवाद आम तौर पर पहले `Caused by` के बाद होता है |
| `OutOfMemoryError` | आवंटित मेमोरी काफ़ी नहीं |
| `UnsupportedClassVersionError` | Java वर्ज़न और गेम वर्ज़न मेल नहीं खाते |
| `NoSuchMethodError`, `ClassNotFoundException` | मॉड गेम वर्ज़न या लोडर वर्ज़न से मेल नहीं, या डिपेंडेंसी छूटी है |
| `GLFW error` | GPU ड्राइवर या OpenGL सपोर्ट में समस्या |

## 4. आम वजहें

| लक्षण | आम वजह | क्या करें |
| --- | --- | --- |
| लॉन्च होते ही बंद, लॉग में `UnsupportedClassVersionError` | Java वर्ज़न गलत | GPCL से Java अपने आप इंस्टॉल कराएँ; या सेटिंग्स में मिरर बदलकर दोबारा इंस्टॉल करें |
| लोड होते-होते अटक जाए या बंद हो जाए, लॉग में `OutOfMemoryError` | मेमोरी कम, या मॉड बहुत ज़्यादा | सेटिंग्स → गेम → मेमोरी आवंटन में बढ़ाएँ; फ़िज़िकल मेमोरी से ज़्यादा न दें |
| मॉड लोड करते समय क्रैश, लॉग में मॉड का नाम | मॉड वर्ज़न गलत, डिपेंडेंसी छूटी, दो मॉड आपस में टकरा रहे | पहले सिर्फ़ यही मॉड इंस्टॉल करके आज़माएँ; देखें कि यह किन MC और लोडर वर्ज़न को सपोर्ट करता है |
| विंडो आने से पहले बंद, `GLFW error` | GPU ड्राइवर पुराना, या OpenGL का सपोर्ट नहीं | GPU ड्राइवर अपडेट करें; लैपटॉप पर पक्का करें कि गेम डेडिकेटेड GPU पर चल रहा है |
| सर्वर से किक, `Invalid session` | प्रीमियम लॉगिन एक्सपायर, या अकाउंट के पास इस वर्ज़न का लाइसेंस नहीं | दोबारा प्रीमियम लॉगिन करें; पक्का करें कि अकाउंट के पास यह वर्ज़न है |
| दुनिया में जाते समय या रिसोर्स पैक लोड करते समय क्रैश | सेव, रिसोर्स पैक या शेडर पैक खराब | पहले नई दुनिया बनाकर आज़माएँ; सेव का बैकअप लेकर फिर संभालें |
| Fabric से लॉन्च पर क्रैश, `fabric-api` छूटने का संदेश | Fabric API इंस्टॉल नहीं | Fabric दोबारा इंस्टॉल करते समय "साथ में Fabric API इंस्टॉल करें" चुनें, या हाथ से इंस्टॉल करें |

## 5. पहले ये तीन चीज़ें अलग करें

1. **सारे मॉड, रिसोर्स पैक और शेडर बंद करें** और एक बार बिना कुछ चलाएँ। चल जाए तो समस्या मॉड की तरफ़ है।
2. **दूसरा वनीला वर्ज़न चलाएँ**। चल जाए तो मौजूदा वर्ज़न या उसके मॉड संयोजन में दिक्कत है।
3. **नई दुनिया बनाएँ**। चल जाए तो पुराना सेव खराब है।
