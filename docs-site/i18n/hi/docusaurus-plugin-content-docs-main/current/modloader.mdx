डाउनलोड पेज पर वर्ज़न चुनते समय सीधे लोडर भी चुना जा सकता है। GPCL पहले वनीला इंस्टॉल करता है, फिर लोडर को अलग वर्ज़न डायरेक्टरी में इंस्टॉल करता है — वनीला पर कुछ नहीं लिखा जाता।

## कैसे इंस्टॉल करें

1. डाउनलोड पेज खोलें और एक Minecraft वर्ज़न चुनें।
2. लोडर विकल्पों में Forge, Fabric या OptiFine चुनें, फिर उसका लोडर वर्ज़न चुनें।
3. डाउनलोड पर क्लिक करें और वनीला तथा लोडर, दोनों के इंस्टॉल होने का इंतज़ार करें।
4. लॉन्च पेज पर लौटें और लोडर के नाम वाला वर्ज़न चुनकर चलाएँ।

डाउनलोड टास्क कतार में जाते हैं; कई वर्ज़न एक के बाद एक क्लिक किए जा सकते हैं। चल रहा टास्क रद्द भी किया जा सकता है, रद्द करने पर कतार आगे बढ़ती रहती है।

## तीन लोडर में से कौन-सा

| लोडर | किसके लिए | ध्यान दें |
| --- | --- | --- |
| Forge | बड़े मॉडपैक, पुराने मॉड | Fabric से धीमा शुरू होता है, वर्ज़न बहुत हैं |
| Fabric | हल्के मॉड, नए वर्ज़न | गेम वर्ज़न के हिसाब से सही Fabric Loader चुनना पड़ता है |
| OptiFine | शेडर, प्रदर्शन सुधार | दूसरे लोडर के साथ मिलाकर इस्तेमाल में कम्पैटिबिलिटी मॉड चाहिए हो सकते हैं |

### Forge

इंस्टॉल के समय GPCL सिर्फ़ `--installClient` चलाता है, GUI या सर्वर पैरामीटर आज़माता नहीं। इंस्टॉलर का आउटपुट प्रगति में बदल जाता है, जैसे "Forge इंस्टॉल हो रहा है: Downloading library…"।

इंस्टॉल से पहले Java का बड़ा वर्ज़न जाँचा जाता है; Forge की ज़रूरत से कम हो तो सीधे एरर दिखता है, कम वर्ज़न वाले Java से ज़बरदस्ती नहीं चलाया जाता। पूरी प्रक्रिया ज़्यादा से ज़्यादा 15 मिनट इंतज़ार करती है; डाउनलोड रद्द करने पर इंस्टॉलर प्रोसेस खत्म हो जाता है।

### Fabric

GPCL सीधे Fabric का वर्ज़न प्रोफ़ाइल और लाइब्रेरी फ़ाइलें लेता है, इंस्टॉलर पर निर्भर नहीं।

"साथ में Fabric API इंस्टॉल करें" डिफ़ॉल्ट रूप से चेक है; Fabric इंस्टॉल होने के बाद मेल खाते वर्ज़न का Fabric API उस वर्ज़न के `mods` में डाल दिया जाता है। चेक हटाने पर इंस्टॉल नहीं होगा; Fabric API फेल होने पर सिर्फ़ संदेश दिखता है, Fabric पर असर नहीं।

### OptiFine

OptiFine साइलेंट इंस्टॉल होता है, उसका अपना GUI इंस्टॉलर नहीं खुलता। नतीजा मौजूदा गेम फ़ोल्डर में ही जाता है, कस्टम गेम फ़ोल्डर भी सही तरीके से हैंडल होता है।

## मॉड कहाँ रखें

नए डाउनलोड किए गए वर्ज़न में डिफ़ॉल्ट रूप से **वर्ज़न आइसोलेशन** चालू होता है: गेम डायरेक्टरी `versions/<version-name>` की ओर इशारा करती है, और मॉड, सेव तथा गेम सेटिंग्स उसी वर्ज़न के साथ चलते हैं।

| वर्ज़न की हालत | मॉड डायरेक्टरी |
| --- | --- |
| नया डाउनलोड, आइसोलेटेड | `versions/<version-name>/mods` |
| पहले से है, और वर्ज़न फ़ोल्डर में `mods` / `saves` नहीं | गेम रूट के नीचे `mods` |

लॉन्च पेज पर वर्ज़न की "वर्ज़न सेटिंग्स" खोलें; फ़ोल्डर एंट्री असल आइसोलेशन नतीजे के हिसाब से बनती हैं:

- "वर्ज़न फ़ोल्डर" हमेशा रहता है;
- Forge / Fabric / NeoForge / Quilt मिलने पर "Mod फ़ोल्डर" दिखता है;
- OptiFine मिलने पर "शेडर फ़ोल्डर" दिखता है।

किसी भी डायरेक्टरी में सीधे मॉड इंस्टॉल करने हों, तो मॉड डाउनलोड के इंस्टॉल टारगेट में "फ़ोल्डर चुनें" चुनें — यह उस डायरेक्टरी के अंदर `mods` ढूँढ लेता है।

## इंस्टॉल के बाद क्रैश

1. पहले `mods` के सारे मॉड हटा दें और एक बार बिना मॉड चलाएँ।
2. चल जाए तो हर बार आधे मॉड वापस डालें और समस्या वाला मॉड ढूँढें।
3. पक्का करें कि मॉड Minecraft वर्ज़न और लोडर वर्ज़न दोनों से मेल खाता है — Forge का मॉड Fabric में सीधे नहीं डाला जा सकता, और उलटा भी वैसा ही।
4. ज़रूरी डिपेंडेंसी न होने पर भी लॉन्च के समय क्रैश होता है; पहले [मॉड डाउनलोड](./mods.mdx) में देखें कि कौन-कौन सी डिपेंडेंसी ज़रूरी बताई गई हैं।

OptiFine को Forge / Fabric के साथ मिलाने पर आम तौर पर अलग कम्पैटिबिलिटी मॉड चाहिए होते हैं। सही कम्पैटिबिलिटी मॉड के बिना ज़बरदस्ती न करें।

और जाँच के कदम [गेम क्रैश](./mc-game.mdx) में हैं।
