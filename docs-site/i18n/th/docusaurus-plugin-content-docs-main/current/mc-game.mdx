หน้าต่างแครชมักบอกสาเหตุไม่ได้เอง GPCL จะอ่านบันทึกหนึ่งรอบเพื่อให้เบาะแส แล้วตรวจสอบตามลำดับด้านล่าง

:::tip ทำสิ่งหนึ่งก่อน
กด "ส่งออกรายงานข้อผิดพลาด" บนหน้าต่างแจ้งเตือนแครช แล้วบันทึกไฟล์ zip ที่ได้ ต้นรายงานคือผลการวิเคราะห์ของ GPCL ต่อด้วยรายการ Mod, Java, พารามิเตอร์เปิดเกม และบันทึกทั้งหมด การตรวจสอบส่วนใหญ่พึ่งมัน
:::

## 1. ดูการวิเคราะห์ของ GPCL ก่อน

หน้าต่างจะแสดงเบาะแส 1–2 ข้อที่ GPCL พบในบันทึก เช่น "หน่วยความจำไม่พอ" หรือ "การตรวจสอบการพึ่งพาหรือความเข้ากันได้ของ Mod ไม่ผ่าน" กด "ดูรายละเอียด" เพื่อดูเบาะแสทั้งหมด ข้อความบันทึกต้นฉบับที่ตรงกัน และข้อมูลการแครช

ข้อสรุปเหล่านี้อาศัยการจับคู่คำสำคัญ ใช้เป็นทิศทางในการตรวจสอบเท่านั้น เมื่อบันทึกมีข้อมูลที่เฉพาะเจาะจงกว่า (เช่นขาดสิ่งที่ต้องมีก่อนตัวไหน) จะถูกระบุไว้ในหลักฐานด้วย

## 2. ส่งออกรายงานข้อผิดพลาด

ปุ่มนี้อยู่บนหน้าต่างแครชเลย เลือกตำแหน่งบันทึก GPCL จะแพ็กเป็น:

- `error-report.txt`: ผลการวิเคราะห์ สรุปข้อผิดพลาด ระบบ / การ์ดจอ / Java รายการ Mod แพ็กทรัพยากรและเชดเดอร์ พารามิเตอร์เปิดเกม เอาต์พุตเกม บรรทัดข้อผิดพลาดในบันทึก;
- `crash-reports/`: รายงานแครชที่สร้างจากการแครชครั้งนี้;
- `logs/`: `latest.log` และ `debug.log` (หากใหญ่เกินไปเก็บเฉพาะส่วนท้าย);
- `jvm-crash/`: `hs_err_pid*.log` ที่ JVM เขียนเอง (หากปัญหาเช่นไดรเวอร์การ์ดจอทำให้ JVM แครช);
- `launcher-log.txt`: บันทึกของตัวเปิดเกม;
- `game-output.txt`: เอาต์พุตมาตรฐานและเอาต์พุตข้อผิดพลาดของโปรเซสเกมในการรันครั้งนี้

`--accessToken` และชื่อผู้ใช้ระบบในรายงานถูกปิดบังแล้ว ส่งออกไปได้เลย อย่าส่งแค่ภาพหน้าจอของหน้าต่างแครช

## 3. ดูบันทึกเองก่อน

"ดูบันทึก" บนหน้าต่างจะเปิดเอาต์พุตของโปรเซสเกม ให้ดูส่วนล่างสุด และค้นคำเหล่านี้:

| คำสำคัญ | มักหมายถึง |
| --- | --- |
| `Exception`, `Caused by` | ข้อยกเว้นจริงมักอยู่หลัง `Caused by` ตัวแรก |
| `OutOfMemoryError` | หน่วยความจำที่จัดสรรไม่พอ |
| `UnsupportedClassVersionError` | เวอร์ชัน Java กับเวอร์ชันเกมไม่ตรงกัน |
| `NoSuchMethodError`, `ClassNotFoundException` | มอดไม่ตรงกับเวอร์ชันเกม เวอร์ชันตัวโหลด หรือขาดสิ่งที่ต้องมีก่อน |
| `GLFW error` | ไดรเวอร์การ์ดจอหรือการรองรับ OpenGL มีปัญหา |

## 4. สาเหตุที่พบบ่อย

| อาการ | สาเหตุที่พบบ่อย | วิธีจัดการ |
| --- | --- | --- |
| เปิดแล้วออกทันที บันทึกมี `UnsupportedClassVersionError` | เวอร์ชัน Java ไม่ถูกต้อง | ให้ GPCL ติดตั้ง Java ให้อัตโนมัติ; หรือเปลี่ยนแหล่งมิเรอร์ในการตั้งค่าแล้วติดตั้งใหม่ |
| โหลดได้ครึ่งทางแล้วค้างหรือเด้ง บันทึกมี `OutOfMemoryError` | หน่วยความจำไม่พอ หรือมอดเยอะเกินไป | เพิ่มใน การตั้งค่า → เกม → การจัดสรรหน่วยความจำ; อย่าเกินหน่วยความจำกายภาพ |
| แครชตอนโหลดมอด บันทึกมีชื่อมอด | เวอร์ชันมอดไม่ถูกต้อง ขาดสิ่งที่ต้องมีก่อน มอดสองตัวขัดกัน | ลองติดตั้งเฉพาะมอดนี้ก่อน; ยืนยันเวอร์ชัน MC และเวอร์ชันตัวโหลดที่มันรองรับ |
| ออกก่อนหน้าต่างจะขึ้น มี `GLFW error` | ไดรเวอร์การ์ดจอเก่าเกินไป หรือไม่รองรับ OpenGL | อัปเดตไดรเวอร์การ์ดจอ; โน้ตบุ๊กยืนยันว่าเกมใช้การ์ดจอแยก |
| เข้าเซิร์ฟเวอร์แล้วถูกเตะ แจ้ง `Invalid session` | การเข้าสู่ระบบอย่างเป็นทางการหมดอายุ หรือบัญชีไม่มีสิทธิ์เวอร์ชันนี้ | เข้าสู่ระบบอย่างเป็นทางการใหม่; ยืนยันว่าบัญชีเป็นเจ้าของเวอร์ชันนั้นจริง |
| แครชตอนเข้าดาวหรือโหลดแพ็กทรัพยากร | เซฟ แพ็กทรัพยากร หรือแพ็กเชดเดอร์เสียหาย | สร้างดาวใหม่ลองก่อน; สำรองเซฟก่อนจัดการ |
| ใช้ Fabric เปิดแล้วแครชทันที แจ้งขาด `fabric-api` | ยังไม่ได้ติดตั้ง Fabric API | ตอนติดตั้ง Fabric ใหม่ให้ติ๊ก "ติดตั้ง Fabric API ด้วย" หรือติดตั้งเพิ่มเอง |

## 5. ตัดสามอย่างนี้ออกก่อน

1. **ปิดมอด แพ็กทรัพยากร และเชดเดอร์ทั้งหมด** เปิดเกมเปล่าหนึ่งครั้ง เข้าได้แสดงว่าปัญหาอยู่ที่มอด
2. **เปลี่ยนไปเปิดเวอร์ชันต้นฉบับอื่น** เข้าได้แสดงว่าเวอร์ชันปัจจุบันหรือชุดมอดของมันมีปัญหา
3. **สร้างโลกใหม่** เข้าได้แสดงว่าเซฟเดิมเสีย
