ডাউনলোড ধীর হওয়া সাধারণত লঞ্চারের সমস্যা নয়। আগে ডাউনলোড সোর্স বদলান, তারপর থ্রেড সংখ্যা ও স্পিড লিমিট ভাবুন।

## ডাউনলোড টাস্ক কিউতে যায়

"ডাউনলোড"-এ ক্লিক করলে টাস্ক কিউতে যায়, পুরো ইন্টারফেস আটকে যায় না: অপেক্ষারত টাস্ক ×-এ ক্লিক করে সরানো যায়, চলমান টাস্ক বাতিল করা যায়, বাতিলের পরে কিউ চলতে থাকে।

ডাউনলোড পেজ প্রতিটি টাস্কের অবস্থা দেখায়: অপেক্ষায়, ডাউনলোড হচ্ছে, সম্পন্ন, ব্যর্থ।

## ফাইল ডাউনলোড সোর্স বনাম ভার্সন লিস্ট সোর্স

**সেটিংস → ডাউনলোড → ডাউনলোড সোর্স**-এ দুটি ড্রপডাউন, প্রতিটি আলাদা:

- **ফাইল ডাউনলোড সোর্স**: ক্লায়েন্ট jar, অ্যাসেট ফাইল, নির্ভরশীল লাইব্রেরি;
- **ভার্সন লিস্ট সোর্স**: ভার্সন ম্যানিফেস্ট, ভার্সন JSON, অ্যাসেট ইনডেক্স।

দুটোতেই একই চারটি অপশন:

| অপশন | আচরণ |
| --- | --- |
| অফিসিয়াল আগে, ধীর হলে মিরর | ডিফল্ট। আগে অফিসিয়ালে সংযোগ, কয়েক সেকেন্ড সাড়া না পেলে BMCLAPI-তে |
| মিরর যতটা সম্ভব ব্যবহার | চীনা নেটওয়ার্কে সরাসরি মিরর |
| অফিসিয়াল সোর্স আগে | আগে অফিসিয়াল, ব্যর্থ হলে মিরর |
| অফিসিয়াল সোর্স যতটা সম্ভব | শুধু অফিসিয়াল, সংযোগ না হলে ব্যর্থ |

## কাস্টম ফাইল মিরর

**সেটিংস → ডাউনলোড → কাস্টম ফাইল মিরর**-এ মিররের রুট ঠিকানা লেখা যায় (ডিফল্ট BMCLAPI, যেমন `https://bmclapi2.bangbang93.com`)। লেখার পরে ভার্সন ম্যানিফেস্ট, ক্লায়েন্ট, লাইব্রেরি ও অ্যাসেট আগে এটি দিয়েই যায়, না পেলে পুরোনো সোর্স ক্রমে ফলব্যাক হয়।

খালি রাখলে ডিফল্ট BMCLAPI-ই থাকে।

## গেম ফোল্ডার

**সেটিংস → ডাউনলোড → গেম ফোল্ডার**-এ ভার্সন, লাইব্রেরি, অ্যাসেট ও মড যেকোনো ফোল্ডারে রাখা যায়; খালি রাখলে `%APPDATA%\gpcl\.minecraft`-এ ফিরে যায়।

ফোল্ডার বদলালে পুরোনো ফাইল **নিজে থেকে সরানো হয় না**। পুরোনো ফোল্ডারের ভার্সন সঙ্গে যায় না, দরকার হলে নিজে কপি করুন; কনফিগ ও লগ এখনও `%APPDATA%\gpcl`-এ থাকে।

## সর্বোচ্চ থ্রেড সংখ্যা

ডিফল্ট 64, রেঞ্জ 1–128। ছোট ফাইল বেশি থাকলে সমান্তরালতা বাড়ালে দ্রুত হয়, তবে খুব বেশি হলে নেটওয়ার্ক ডিভাইস বা মিরর লিমিট করতে পারে। নেটওয়ার্ক অস্থির হলে কমিয়ে দিন।

## স্পিড লিমিট

0 মানে কোনো লিমিট নেই; মান লিখলে **সব ডাউনলোড টাস্ক এই মোট সীমা ভাগ করে**, একক MB/s, আর পরের ডাউনলোড শুরুর সময় কার্যকর হয়। শেয়ার করা নেটওয়ার্কে কমিয়ে দেওয়া যায়।

এই লিমিট শুধু গেম অ্যাসেট ডাউনলোডে কাজ করে। Java রানটাইম আলাদা মিরর দিয়ে ডাউনলোড হয়, এখান থেকে প্রভাবিত হয় না।

## Java মিরর

**সেটিংস → ডাউনলোড → Java ডাউনলোড**-এ সিংহুয়া বিশ্ববিদ্যালয়, নানজিং বিশ্ববিদ্যালয়, হুয়াওয়ে ক্লাউড বা কাস্টম বাছা যায়। নির্বাচিত সোর্স ব্যর্থ হলে নিজে থেকেই পরেরটায় যায়, শেষে Adoptium-এর অফিসিয়াল সোর্স ব্যাকআপ আছে।

কাস্টম ঠিকানায় দুটি ভেরিয়েবল সমর্থিত:

- `{v}`: Java-র বড় ভার্সন, যেমন `8`, `17`, `21`;
- `{version}`: আপস্ট্রিমের পূর্ণ ভার্সন নম্বর, যেমন `17.0.20.1_1` — আপস্ট্রিম রিলিজের সঙ্গে বদলায়।

উদাহরণ:

```text
https://cdn.example.com/java/{v}/OpenJDK{v}U-jre_x64_windows_hotspot_{v}.zip
```

## ডাউনলোড ব্যর্থ হলে আগে কী করবেন

1. ডাউনলোড সোর্স বদলান।
2. থ্রেড সংখ্যা 32 বা 16 করে আবার চেষ্টা করুন।
3. সিস্টেমের সময় ঠিক আছে কি না দেখুন — বেশি ফারাক থাকলে HTTPS সার্টিফিকেট যাচাই ব্যর্থ হয়।
4. তাতেও না হলে মেইল করুন, সঙ্গে `%APPDATA%\gpcl\gpcl\log`-এর সবচেয়ে নতুন লগ।
