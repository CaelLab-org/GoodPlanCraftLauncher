下載慢通常不是啟動器的問題。先換下載來源，再考慮執行緒數和限速。

## 下載任務會排隊

點「下載」後任務會進佇列，不會卡住整個介面：等待中的任務可以點 × 移除，正在下載的任務可以取消，取消後佇列繼續執行。

下載頁會列出每個任務的狀態：等待中、下載中、完成、失敗。

## 檔案下載來源 vs 版本清單來源

**設定 → 下載 → 下載來源** 裡有兩個下拉式選單，各自獨立：

- **檔案下載來源**：用戶端 jar、資源檔案、依賴庫；
- **版本清單來源**：版本清單、版本 JSON、資源索引。

兩個都有同樣的四個選項：

| 選項 | 行為 |
| --- | --- |
| 優先官方，緩慢時換鏡像 | 預設。先連官方，幾秒沒回應就換 BMCLAPI |
| 盡量使用鏡像來源 | 中國大陸網路直接用鏡像 |
| 優先使用官方來源 | 先官方，失敗了再回鏡像 |
| 盡量使用官方來源 | 只用官方，官方連不上就失敗 |

## 自訂檔案鏡像

**設定 → 下載 → 自訂檔案鏡像** 可以填一個鏡像根位址（預設 BMCLAPI，例如 `https://bmclapi2.bangbang93.com`）。填了之後，版本清單、用戶端、庫和資源都優先走它，拉不到再按原本的來源順序備援。

留空就是預設 BMCLAPI。

## 遊戲目錄

**設定 → 下載 → 遊戲目錄** 可以把版本、庫、資源和模組放到任意資料夾；留空回到 `%APPDATA%\gpcl\.minecraft`。

切換目錄**不會自動搬移**既有檔案。舊目錄裡的版本不會跟著過去，需要的話自己複製；設定和日誌仍然在 `%APPDATA%\gpcl`。

## 最大執行緒數

預設 64，範圍 1-128。小檔案多的時候提高並行數會快一些，但太高可能被網路設備或鏡像限流。網路不穩定就往下調。

## 速度限制

0 表示不限速；填了數值後，**所有下載任務共用這個總上限**，單位 MB/s，下次下載開始時生效。多人共用網路時可以調低。

這個限制只作用於遊戲資源下載。Java 執行環境使用單獨的鏡像下載，不受這裡影響。

## Java 鏡像來源

**設定 → 下載 → Java 下載** 裡可以選清華大學、南京大學、華為雲或自訂。選中的源失敗時會自動換下一個，最後還有 Adoptium 官方備援。

自訂位址支援兩個變數：

- `{v}`：Java 大版本，例如 `8`、`17`、`21`；
- `{version}`：上游完整版本號，例如 `17.0.20.1_1`，會隨上游發布變化。

範例：

```text
https://cdn.example.com/java/{v}/OpenJDK{v}U-jre_x64_windows_hotspot_{v}.zip
```

## 下載失敗先做什麼

1. 換一個下載來源。
2. 把執行緒數降到 32 或 16 再試。
3. 確認系統時間正確 —— 時間偏差太大會導致 HTTPS 憑證驗證失敗。
4. 還不行就寄信，附上 `%APPDATA%\gpcl\gpcl\log` 裡最新的日誌。
