崩溃窗口本身通常看不出原因。GPCL 会先读一遍日志给出线索，再按下面的顺序排查。

:::tip 先做一件事
点崩溃弹窗上的「导出错误报告」，把生成的 zip 保存下来。报告开头就是 GPCL 的分析结果，后面还有 Mod 列表、Java、启动参数和所有日志，排查基本都靠它。
:::

## 1. 先看 GPCL 的分析

弹窗会显示 GPCL 从日志里找到的 1–2 条线索，比如「内存不足」「Mod 依赖或兼容性检查没通过」。点「查看详情」能看到全部线索、对应的日志原文和崩溃信息。

这些结论是照着关键词匹配出来的，只能当作排查方向。日志里有更具体的信息时（比如缺少哪个前置），会一并列在证据里。

## 2. 导出错误报告

崩溃弹窗上就有这个按钮。选一个位置保存，GPCL 会打包成：

- `error-report.txt`：分析结果、错误摘要、系统 / 显卡 / Java、Mod 列表、资源包与光影、启动参数、游戏输出、日志里的错误行；
- `crash-reports/`：这次崩溃生成的崩溃报告；
- `logs/`：`latest.log` 和 `debug.log`（过大时只保留末尾部分）；
- `jvm-crash/`：JVM 自己写出的 `hs_err_pid*.log`（如果显卡驱动之类的问题导致 JVM 崩溃）；
- `launcher-log.txt`：启动器日志；
- `game-output.txt`：游戏进程这次运行的标准输出和错误输出。

报告里的 `--accessToken` 和系统用户名已经打码，可以直接发出去。不要只发崩溃窗口的截图。

## 3. 自己先看日志

弹窗上的「查看日志」会打开游戏进程的输出。重点看最底部，以及搜这几个词：

| 关键词 | 通常意味着 |
| --- | --- |
| `Exception`、`Caused by` | 真正的异常通常在第一个 `Caused by` 后面 |
| `OutOfMemoryError` | 分配的内存不够 |
| `UnsupportedClassVersionError` | Java 版本和游戏版本对不上 |
| `NoSuchMethodError`、`ClassNotFoundException` | 模组与游戏版本、加载器版本不匹配，或缺前置 |
| `GLFW error` | 显卡驱动或 OpenGL 支持有问题 |

## 4. 常见原因

| 现象 | 常见原因 | 怎么处理 |
| --- | --- | --- |
| 一启动就退出，日志里有 `UnsupportedClassVersionError` | Java 版本不对 | 让 GPCL 自动补 Java；或在设置里换镜像源后重新安装 |
| 加载到一半卡死或闪退，日志里有 `OutOfMemoryError` | 内存不够，或模组太多 | 设置 → 游戏 → 内存分配里调大；不要超过物理内存 |
| 加载模组时崩，日志里出现模组名 | 模组版本不对、缺前置、两个模组冲突 | 先只装这个模组试；确认它支持的 MC 版本和加载器版本 |
| 窗口还没出来就退出，有 `GLFW error` | 显卡驱动过旧，或 OpenGL 不支持 | 更新显卡驱动；笔记本确认游戏用的是独显 |
| 进服务器被踢，提示 `Invalid session` | 正版登录过期，或账号没有这个版本的授权 | 重新登录正版；确认账号确实拥有该版本 |
| 进世界或加载资源包时崩 | 存档、资源包或光影包损坏 | 先新建一个世界试；把存档备份出来再处理 |
| 用 Fabric 启动就崩，提示缺 `fabric-api` | 没装 Fabric API | 重新装 Fabric 时勾上「同时安装 Fabric API」，或手动补装 |

## 5. 先排除这三件事

1. **关掉所有模组、资源包和光影**，裸启动一次。能进就是模组那边的问题。
2. **换一个原版版本启动**。能进就是当前版本或它的模组组合有问题。
3. **新建一个世界**。能进就是原来的存档坏了。

## 6. 还是不行

发邮件到 [gamets@caellab.com](mailto:gamets@caellab.com)，附上导出的错误报告，再写清楚：

- 启动器版本、Minecraft 版本、加载器版本；
- 装了哪些模组（有版本号更好）；
- 崩溃前做了什么。

只描述「一启动就崩」很难定位，报告里的日志才是关键。
