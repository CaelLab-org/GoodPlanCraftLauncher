下载慢通常不是启动器的问题。先换下载源，再考虑线程数和限速。

## 下载任务会排队

点「下载」后任务会进队列，不会卡住整个界面：等待中的任务可以点 × 移除，正在下载的任务可以取消，取消后队列继续执行。

下载页会列出每个任务的状态：等待中、下载中、完成、失败。

## 文件下载源 vs 版本列表源

**设置 → 下载 → 下载源** 里有两个下拉，各自独立：

- **文件下载源**：客户端 jar、资源文件、依赖库；
- **版本列表源**：版本清单、版本 JSON、资源索引。

两个都有同样的四个选项：

| 选项 | 行为 |
| --- | --- |
| 优先官方，缓慢时换镜像 | 默认。先连官方，几秒没响应就换 BMCLAPI |
| 尽量使用镜像源 | 国内网络直接用镜像 |
| 优先使用官方源 | 先官方，失败了再回镜像 |
| 尽量使用官方源 | 只用官方，官方连不上就失败 |

## 自定义文件镜像

**设置 → 下载 → 自定义文件镜像** 可以填一个镜像根地址（默认 BMCLAPI，例如 `https://bmclapi2.bangbang93.com`）。填了之后，版本清单、客户端、库和资源都优先走它，拉不到再按原来的源顺序兜底。

留空就是默认 BMCLAPI。

## 游戏目录

**设置 → 下载 → 游戏目录** 可以把版本、库、资源和模组放到任意文件夹；留空回到 `%APPDATA%\gpcl\.minecraft`。

切换目录**不会自动搬迁**已有文件。旧目录里的版本不会跟着过去，需要的话自己复制；配置和日志仍然在 `%APPDATA%\gpcl`。

## 最大线程数

默认 64，范围 1–128。小文件多的时候提高并发会快一些，但太高可能被网络设备或镜像限流。网络不稳定就往下调。

## 速度限制

0 表示不限速；填了数值后，**所有下载任务共享这个总上限**，单位 MB/s，下次下载开始时生效。多人共用网络时可以调低。

这个限制只作用于游戏资源下载。Java 运行时使用单独的镜像下载，不受这里影响。

## Java 镜像源

**设置 → 下载 → Java 下载** 里可以选清华大学、南京大学、华为云或自定义。选中的源失败时会自动换下一个，最后还有 Adoptium 官方兜底。

自定义地址支持两个变量：

- `{v}`：Java 大版本，例如 `8`、`17`、`21`；
- `{version}`：上游完整版本号，例如 `17.0.20.1_1`，会随上游发布变化。

示例：

```text
https://cdn.example.com/java/{v}/OpenJDK{v}U-jre_x64_windows_hotspot_{v}.zip
```

## 下载失败先做什么

1. 换一个下载源。
2. 把线程数降到 32 或 16 再试。
3. 确认系统时间正确 —— 时间偏差太大会导致 HTTPS 证书校验失败。
4. 还不行就发邮件，附上 `%APPDATA%\gpcl\gpcl\log` 里最新的日志。
